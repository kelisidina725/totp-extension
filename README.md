# TOTP 验证码管理器

本地生成 TOTP 验证码，支持手动添加、扫码导入与现有密钥库迁移。

这是一个 Manifest V3 浏览器扩展。它只在本地读取密钥、按 RFC 6238 计算验证码，密钥保存在当前浏览器配置文件里，不上传到任何服务器。程序平时不发起网络请求，界面里的二维码识别用的也是随包附带的本地库。文末写清了数据边界和免责声明，用之前先看一眼。

## 用来做什么

装好扩展后，浏览器工具栏的图标就是验证码入口。点开图标，列表里每条账号显示当前验证码、剩余秒数和一个环形进度条；秒数进入最后 5 秒时，验证码和进度条会变色提示即将轮换。点任意一条账号卡片，验证码复制到剪贴板，上方会弹出短暂提示。列表上方有搜索框，按账号名或发行方名称过滤；每条卡片右侧有「改」（重命名）和「×」（删除）两个按钮，删除前会二次确认。

验证码默认每 30 秒轮换一次，显示时按前后各一半分组（例如 `123 456`），复制时是不带空格的原始 6 位数字。算法、位数和周期都跟随账号自身的设置，管理页里可以看到每条账号的具体参数。

要添加账号、整理密钥库或做备份，点工具栏面板右上角的「＋」或底部的「管理全部账号」，进入独立的标签页管理界面。

## 开始之前

- 支持 Manifest V3 的 Chromium 系浏览器（Chrome、Edge 等）。Firefox 未适配。
- 到 [Releases 页面](https://github.com/kelisidina725/totp-extension/releases/latest) 下载 `totp-extension-v1.0.0.zip`，解压到一个固定目录。这个目录在浏览器使用期间不能删除或移动。
- 打开 `chrome://extensions`（Edge 是 `edge://extensions`），开启「开发者模式」，点「加载已解压的扩展程序」，选中刚才解压的目录。浏览器不会自动更新这个目录里的代码，升级时替换文件后到扩展页点一次刷新。
- 也可以直接从源码仓库加载，方式相同，不需要构建步骤。

首次打开时列表为空，提示用三种方式添加账号。管理页顶部有本机存储提示：密钥只保存在本浏览器本地存储中。

## 添加账号

管理页左侧的「添加账号」区域有三个标签：手动添加、扫码导入、迁移密钥库。三种方式都会先做参数校验，再检查密钥是否已存在；相同密钥不会重复添加，界面会提示已跳过。

### 手动添加

填写名称与 Base32 密钥，选择位数（6 / 7 / 8）、周期（30 / 60 秒）和算法（SHA1 / SHA256 / SHA512）。密钥输入框旁边的眼睛按钮可以切换明文显示。

填写过程中下方预览区实时显示当前验证码和剩余秒数；密钥非法、算法不支持或参数不完整时，预览区直接给出错误原因，不会写入列表。确认无误后点「添加账号」。

Base32 密钥允许小写、空格和连字符，添加时会自动去掉分隔符并转成大写。程序会校验每个字符是否属于 Base32 字母表，非法字符会被拒绝。

### 扫码导入

这个方式处理的是二维码图片，不需要摄像头，也不调用在线解码服务。复制二维码截图后在管理页按 `Ctrl+V` 粘贴，或者点「粘贴识别」主动读取剪贴板图片，也可以点「上传二维码图片」从本地选文件。

识别成功后预览区显示账号名、算法、位数和周期，确认无误再点「确认添加」。识别不到二维码、图片里不是 `otpauth://` 凭证、或者凭证类型是 HOTP 时，会在预览区说明原因，不会写入列表。

剪贴板读取在部分浏览器里需要站点权限；如果按钮提示当前环境不支持读取剪贴板，直接用 `Ctrl+V` 粘贴即可，这条路径不需要额外授权。

### 迁移密钥库

迁移标签用于把别的工具或旧版本导出的凭证搬进来。支持三类输入：

- `.neustorage` 或普通 JSON 备份文件（数组，或带 `accounts` 数组的对象），文件选择框支持 `.neustorage` / `.json` / `.txt`；
- 单行或多行 `otpauth://totp/...` 凭证文本，可以整段粘贴，也可以从文本文件读取，混杂在说明文字里的凭证会被逐行提取；
- 本扩展自己导出的备份 JSON。

填入文本或选择文件后会自动解析，先显示本次解析出多少个账号、跳过了多少条无效记录，再点「导入账号」才会写入。逐条校验失败的凭证会被跳过，其余正常导入；如果一条都没有，界面只显示错误原因，不会改动现有数据。HOTP 凭证在解析阶段会被跳过，本扩展只处理 TOTP。

## 备份与恢复

管理页右上角和账号列表底部都有「导出备份」按钮，导出文件名为 `totp-accounts-backup.json`，内容是所有账号的明文 JSON，包含密钥。列表底部的「导入备份」按钮可以把它导回来。

备份文件和迁移标签里的密钥库一样，都走相同的去重逻辑：相同密钥不会重复添加。换浏览器或换电脑时，导入备份是最省事的方式。

备份 JSON 不加密。放进网盘、共享目录或聊天工具之前，先确认你能接受明文密钥离开本机；不要把它发到公开渠道。

## 数据边界

程序不联网。验证码由 Web Crypto API 在本地计算，二维码由随包附带的 jsQR 在本地解码，导入解析也在本地完成。没有账号系统，没有遥测，没有云同步。

它只读写这些位置：

| 用途 | 位置 |
| --- | --- |
| 账号与密钥 | 当前浏览器配置文件的 `chrome.storage.local`（扩展数据） |
| 剪贴板 | 复制验证码时写入；扫码时可读取图片（需用户主动粘贴或点击） |
| 备份文件 | 用户通过系统保存框选择的本地路径 |

扩展申请的权限只有 `storage`、`clipboardRead` 和 `clipboardWrite`。卸载扩展、清除浏览器站点数据或重置浏览器配置文件，都会让密钥一并消失，且无法从服务端找回。

浏览器扩展的本地存储按配置文件隔离。同一台机器上换用户配置文件、换浏览器或换设备，都需要用备份文件迁移，不会自动同步。

## 兼容性与已知限制

- 只生成 TOTP。基于计数器的 HOTP 凭证会被解析但不会导入。
- 算法支持 SHA1、SHA256、SHA512；位数支持 6、7、8，超出范围的参数会被规范化为默认值。周期为 30 或 60 秒，其它值会被规范化为 30 秒。
- 时间是本机系统时间。系统时间偏差会直接导致验证码无效，先校准时间再排查其它原因。
- 验证码按 RFC 6238 标准实现，`tests/totp.test.js` 覆盖了标准测试向量和导入解析路径。
- 二维码识别针对截图，不支持调用摄像头实时扫描；需要一台能显示二维码的设备和一个截图工具。

## 从源码运行

不需要安装依赖，也不需要构建。加载方式见「开始之前」；核心算法和解析器同时提供 CommonJS 导出，可以直接在 Node 里跑测试：

```
node --test tests/*.test.js
```

仓库目录说明：

| 路径 | 用途 |
| --- | --- |
| `manifest.json` | 扩展清单，版本号在这里定义 |
| `popup.html` / `popup.css` / `popup.js` | 工具栏弹出面板 |
| `add.html` / `add.css` / `add.js` | 管理标签页 |
| `totp.js` | RFC 6238 算法实现 |
| `otpauth.js` | `otpauth://` 与 JSON 密钥库解析 |
| `lib/jsQR.js` | 随包附带的二维码解码库 |
| `icons/` | 扩展图标 |
| `tests/` | 算法与解析器测试 |
| `tools/make_icons.py` | 图标生成脚本，运行时不需要 |

Release 的 zip 包只收录运行必需的文件，不含 `tests/` 和 `tools/`。
